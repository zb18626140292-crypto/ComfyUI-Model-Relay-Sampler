# ComfyUI Model Relay Sampler

用于让两个模型在共同 sigma 边界接力，而不是把多个完整 KSampler 串联。
支持第一采低分辨率构图、阶段间潜变量放大和第二采高分辨率重绘。

## 本次更新（2026-10-17）

- K2、Qwen 的双采 SNR/百分比节点支持**自动复用一采结果**，保留原节点和连线。
- 百分比强制按计划步数分配，支持两位小数；8/8 步、37% 为 3+5。
- 两阶段常用控件按“步数 → CFG → 采样器 → 调度器”显示，隐藏兼容用的重绘噪声模式，保存时保留后端顺序。
- Qwen 加速采样器增加原生 KV 缓存安全开关和可选的“高CFG保真”残差缓存策略。
- 大段采样统计不再显示在节点上，必要信息保留在控制台。

这是已有本地更新的整合发布。38 项 CPU/原生执行器回归检查通过，
**不代表已经完成真实 GPU 的画质、耗时、显存峰值或长时间运行验证**。

## Qwen Image 2.1 加速采样器

本仓库同时包含原有模型接力节点和 Qwen Image 2.1 专用节点：

- `Qwen Image 2.1 加速采样器`：一体化单采，支持残差缓存加速。
- `Qwen Image 2.1 双采（百分比）`：两个 Qwen 2.1 模型在共同 sigma 处交接。
- `Qwen Image 2.1 双采（SNR）`：按噪声强度选择交接点。
- `Qwen Image 2.1 Speedup`：供已有 KSampler 工作流使用的模型补丁入口。

Qwen 节点分类为 `采样/Qwen Image 2.1`，旧模型补丁在 `model/patch`。
详细接线、内部放大、参数与历史测试记录见
[Qwen Image 2.1 使用说明](qwen_image_2_1_speedup/README.md)。

Qwen 功能需要已支持 Qwen Image 2.1 的 ComfyUI，使用宿主提供的 PyTorch、
`comfy_api.latest`、`comfy.model_prefetch` 和 `typing_extensions`。
如果缺少这些导入，启动日志会说明 Qwen 节点未载入；原有模型接力节点仍保留。

Qwen 采样器可在模型副本上显式关闭原生 KV 缓存，单采和关闭模型二时也生效。
可选“高CFG保真”会减少 CFG>1 时的残差近似，但没有修改 ComfyUI 原生 KV
缓存实现，也不承诺 CFG=4 在所有模型和工作流下均无错误或无损。详见上述使用说明。

下面各节描述原有模型接力节点；其默认参数与 Qwen 专用节点不同。

## 节点

- `模型接力采样器（双采·百分比）`
- `模型接力采样器（双采·SNR）`

节点分类：`采样/模型接力`

当前版本已将节点参数、连接口和输出口改为中文显示。内部参数键仍保持英文，
因此已有工作流可以继续加载。将鼠标悬停在参数名称或控件上，可以查看用途、
推荐值以及各下拉选项的区别。

百分比和 SNR 已完全拆为两个独立节点，不在同一个节点中切换。

两个节点分别为第一、第二模型建立自己的 sigma 时间表。默认第一采计划
8 步、第二采计划 12 步；百分比 50% 实际执行 4 步和 6 步。百分比直接按
计划步数四舍五入分配，第二采 sigma 对齐第一采的交接噪声；SNR 则按物理
噪声强度匹配时间表。两种模式不互相覆盖，也不保证相同数值对应相同步数。

百分比输入精度为 0.01%，但实际采样仍按整数步执行；相邻小数可能分到
同一个步骤。两边各 8 步时，37% 为 3+5、50% 为 4+4；8/12 步时，37%
为 3+8。百分比不会因最低完成步数保护而自动推迟，未成形时需自行提高比例。

## 一采结果复用

使用 ComfyUI 的原生子图缓存，不额外持有模型权重，也不增加可见开关：

1. 固定种子，将“生成后控制”设为 `fixed`，成功运行一次双采。
2. 保持一采模型、LoRA、提示条件、输入潜变量及有效 sigma 区间不变。
3. 只调整二采 CFG、提示条件、采样器或放大重绘强度等，缓存命中时只运行二采。

种子、一采参数、模型/条件/潜变量、遮罩、batch 或有效交接区间变化时，
会按原生规则重新采样。SNR 模式下更换二采模型、步数或调度器可能改变
一采的交接点，不能强行复用。改变最终尺寸是否可复用，也取决于一采实际
sigma 区间及放大保护是否改变。

二采失败后，已成功完成的一采仍可复用；失败的一采不会留下有效输出。
重启、清理/禁用节点缓存，或缓存因内存压力被淘汰后，需重新运行一采。
这不是磁盘持久化缓存，也不会使不同随机种子的图自动共享一采。

## 单采 / 双采开关

- 双采节点关闭 `启用第二采` 后，会直接退化为单采，交接方式、交接位置和
  Euler 过渡全部失效。
- 被关闭阶段的 MODEL 和 CONDITIONING 使用懒加载，不会请求上游节点执行。

节点的输出数量保持不变。阶段关闭时，对应的中间输出会返回最近一次有效
采样结果，保证已有连接不会因 `None` 而报错。

## 第一采低分辨率、后续采样内部放大

设置 `最终宽度` 和 `最终高度` 后，节点会：

1. 使用输入 latent 的原始小尺寸执行第一采；
2. 第一采在交接处得到干净的低分辨率 latent；
3. 使用所选算法在节点内部只放大这份干净 latent；
4. 在目标尺寸生成正确分布的新噪声，并按 `重绘强度` 限制重新加噪
   上限（默认 1.0），同时保留第二采原有步数；
5. 第二采在最终尺寸继续精修。

受控重新加噪可避免直接放大带噪 latent 造成的彩色噪点，也可避免按原始高
sigma 重新生成造成的双脸、重影和构图重生。启用内部放大时，一采中间输出
为干净 latent，可以接 VAE 解码预览；未放大时，它通常仍是交接处的带噪
latent，不能当作最终成图。

如果 SNR 交接过早，新版 SNR 节点会使用 `放大前最低一采步数` 保护。以
Krea 2 Turbo 的 8 步 Simple 时间表为例，0 dB 只会给第一采约 1 步，远未
形成完整图像；内部放大时默认会自动推迟到至少 4 步。SNR 默认值因此改为
2.4 dB，它在该时间表中本身就约对应 4 步。

宽高都为 0 时保持输入尺寸。只填写一个尺寸时，另一个尺寸按输入宽高比
自动计算。关闭第二采后，如果填写最终宽高，会先调整输入 latent 尺寸，
再由模型一完整采样，而不是仅在输出时插值放大。

默认放大算法为 `bislerp`。例如输入 1024×1024 latent、最终尺寸设置为
2048×2048，第一采只承担 1024 尺寸的计算，后续阶段才承担 2048 尺寸计算。

内部放大同时支持普通的 4D 图像 latent（B×C×H×W）和 Krea 2 工作流中
常见的单帧 5D latent（B×C×1×H×W）；只放大最后两个空间维度，不改变
批次、通道或帧维度。

## 工作方式

1. 分别用两套计划步数与调度器生成 sigma 时间表。
2. 百分比节点按整步比例分配；SNR 节点选择共同物理噪声边界。
3. 一采加入起始噪声，执行到交接位置。
4. 未放大时，二采零噪声接续，不重复注入起始噪声。
5. 内部放大时，先得到干净的一采 latent，再放大、受控加噪并二采重绘。
6. 两阶段分别使用各自连接的 MODEL、正负条件、CFG、采样器和调度器。

“模型一步数”和“模型二步数”是各自完整时间表的计划长度，不表示两边
都会跑满。总实际步数由交接分配决定，不能直接把两个计划步数相加。

## 默认预设

新版双采默认采用 **Krea 2 Turbo 双模型接力**：

- 第一采 8 步计划、第二采 12 步计划，均为 Simple scheduler
- 第一采和第二采均为 Euler / CFG 1.0
- 百分比节点默认 50%，实际约为 4 个低分辨率步骤 + 6 个高分辨率步骤
- SNR 节点默认 2.4 dB，Krea 8 步中第一采约执行 4 步
- 重绘强度 1.0、放大前最低一采步数 4
- `vram_saver` 显存模式

Krea 2 Turbo 是 8 步蒸馏模型。在 ComfyUI 中 `CFG=1.0` 表示不执行
额外的 classifier-free guidance，符合 Turbo 的推荐用法。双采的 8 步是
共同的参考计划，不是两个模型各自再跑完整 8 步。若希望 50% 时总计 8
个实际步骤，可把两边计划都设为 8；当前 8/12 默认会执行 4+6。

## 中间结果

双采会输出最终结果和第一采结果。最终结果保持为第一个输出口。

## 显存策略

`memory_mode` 提供四档策略，模型卸载与 latent 结果缓存是两回事：

- `auto_balance`：估算下一模型所需空间，不足时提前卸载当前模型。
- `vram_saver`：默认。第一采前释放残留模型，每一采完成后卸载当前模型、
  克隆和附加模型并清理显存。
- `speed_first`：尽量让 ComfyUI 保留模型缓存，换取更快的重复执行。
- `offload_after_sampling`：阶段间按自动平衡判断，最后采样完成后卸载；
  同底模不同 LoRA 交接仍保留必要的安全卸载。

## 兼容性模式

- `same_latent_format`：默认且最安全。适合同一模型家族、共享同类 VAE
  潜空间的不同 checkpoint。
- `same_latent_shape`：允许不同潜空间类型，但要求通道数、维度和下采样
  比例一致。只在确认两个模型的 VAE 潜语义兼容时使用。
- `unsafe`：跳过模型间检查。它不会自动完成 4 通道到 16 通道、图像到
  视频、或不同 VAE 潜空间之间的转换。

推荐先用于同一家族内的 checkpoint 接力，例如 SDXL → SDXL、
Illustrious → Illustrious、Flux → Flux。SDXL → Flux、SD1.5 → Flux
这类交接不能只靠“直接续采”可靠完成，需要额外的 VAE 解码/重编码桥，
而且不再是同一个带噪潜变量的无损接力。

多步采样器在分段交接处会重新建立自己的历史，不会自动继承一采的内部
状态。不同模型的采样参数应分别选择；增加二采步数不保证解决解剖或重影问题。

## 安装

可以在 ComfyUI 的 `custom_nodes` 目录运行：

```bash
git clone https://github.com/zb18626140292-crypto/ComfyUI-Model-Relay-Sampler.git
```

仓库入口已同时注册旧接力节点和 Qwen 节点，不需要再独立安装
`qwen_image_2_1_speedup`。不要同时启用独立 Qwen 包与本整合包，以免重复注册同名
节点。已有手动安装的旧包建议先保留备份，再只启用一套同名节点。

也可以手动安装：

将本仓库根目录（包含根 `__init__.py`、`model_relay_sampler.py`、`js/` 和
`qwen_image_2_1_speedup/`）作为一个完整的 `ComfyUI-Model-Relay-Sampler` 文件夹复制到：

`ComfyUI/custom_nodes/`

然后重启 ComfyUI，并在浏览器按 Ctrl+F5 刷新。请更新完整仓库，不能只替换
Python 文件而遗漏 `js/relay_widget_layout.js`。内部一采/二采辅助节点由
后端注册，普通节点菜单不新增入口；一采复用需保留 ComfyUI 原生节点缓存。
